## Installing

Using go v1.27.

```bash
git clone https://evil.djnn.sh/yellow.git
cd yellow/
make          # or: make docker
```

The docker image ships chromium. On the host, katana and httpx download their own
(~150MB) on first run if no chrome is installed.

## Running

Every tool is a `core.Module` (see `core/module.go`), wired in as a library rather
than shelled out. Run any subcommand with `--help` for its flags.

### Directory tree

```bash
./yellow -d djnn.sh
```

Creates `extracted/{assets,code,creds}`, `scans/{infra,nessus,screenshots,ssl}` and
`www/{exploits,tools}` under `djnn.sh/`.

### Passive enumeration

```bash
./yellow osint -d djnn.sh
```

subfinder, assetfinder, dnsx, gau, alterx, dorks, leaker, shodan. Discovered assets
land in `scans/domains.txt`. Each IP is also mapped to its ASN and BGP prefix
(`asn.json`) over DNS via Team Cymru, with Shadowserver as a fallback.

That ASN data is informational and never feeds back into scanning. For a cloud-hosted
target the prefix belongs to the provider and can span millions of unrelated addresses,
so those are flagged `hosting_provider: true`. Treat it as a scope boundary, not a
target list.

### Prune dead hosts

osint returns historical domains, plenty of which are gone. Filter to the live ones:

```bash
./yellow prune -f djnn.sh/scans/domains.txt -o djnn.sh/scans/web-targets.txt
```

### Active scans

```bash
./yellow scan -d djnn.sh/scans/infra --file djnn.sh/scans/web-targets.txt
```

Default pipeline: sitemap, robots.txt, katana crawl, secret scan, tlsx, wappalyzergo,
cvemap, httpx. Opt in to more:

```bash
./yellow scan -d djnn.sh --port-scan          # TCP + service fingerprinting
./yellow scan -d djnn.sh --gobuster           # dir bruteforce, rooted at crawled dirs
./yellow scan -d djnn.sh --nuclei             # downloads ~hundreds of MB of templates
```

Disable the slow defaults with `--no-katana` and `--no-secrets`.

Katana drives a real browser, so it picks up endpoints that only appear once JavaScript
has run. Its URLs feed the secret scan, gobuster and nuclei, bounded by
`--katana-max-urls`.

The secret scan re-fetches each crawled URL and runs the `gitleaks` rule set over it,
writing `secrets.json`. **That file holds raw secret values.** gitleaks is tuned for
source repos, so minified JS throws high-entropy false positives: treat findings as
leads. Rule ID and entropy are recorded so noisy rules are easy to spot.

Port scanning checks every resolved IP against `cdncheck` first. Hosts behind a WAF are
annotated in `portscan.json` and skipped, since you would only be scanning the reverse
proxy. CDN and cloud ranges are annotated but still scanned, because cdncheck files
ordinary cloud compute under `cdn`, and skipping that would drop real origins.

### Fingerprint only

Wappalyzer plus CVE lookup, without the rest of the scan:

```bash
./yellow fingerprint -d djnn.sh/scans/infra --file djnn.sh/scans/web-targets.txt
```

## Environment

All optional. Modules self-skip when their key is absent.

| variable | unlocks |
|---|---|
| `NVD_API_KEY` | faster CVE lookups ([free key](https://nvd.nist.gov/developers/request-an-api-key)); without one NVD allows 5 requests per 30s and yellow sleeps 7s between queries |
| `SHODAN_API_KEY` | the shodan module |
| `LEAKER_PROVIDER_CONFIG` | path to a leaker provider config, e.g. `~/.config/leaker/provider-config.yml` containing `leakcheck: [your-key]` |
| `HTTP_PROXY` | set for you by `-p/--proxy` |
